The Burning Lattice

Four rules, one probability ratio, and a forest that organises itself. Work through the Drossel & Schwabl model one rule at a time, then run it.

01

Three states, nothing else

The world is a square grid. Every cell is in exactly one of three states, and the whole model is about how cells switch between them.

0  empty 1  tree 2  burning

In R the grid is just an integer matrix, and the states are plain integers. Keeping them numeric is what lets us update the entire lattice with a handful of matrix operations instead of a loop over cells.

R/forest_fire.R
# State codes. Kept as integers so the lattice stays a plain integer matrix.
EMPTY   <- 0L
TREE    <- 1L
BURNING <- 2L

A cell has no memory, no age, no species. This is deliberate: the model asks what the minimum ingredients for realistic fire patterns are, and the answer turns out to be very few.

02

Four rules, applied to every cell at once

Each time step, every cell looks at the lattice as it was at the end of the previous step and applies these rules. Rules i–iii were the earlier Bak–Chen–Tang model; rule iv, the lightning, is what Drossel and Schwabl added.

i

A burning tree becomes an empty site.

burning → empty, always

ii

A tree becomes burning if at least one of its four nearest neighbours is burning.

tree → burning, if a neighbour burns

iii

An empty site grows a tree with probability p.

empty → tree, with probability p

iv

A tree with no burning neighbour is struck by lightning, and starts burning, with probability f.

tree → burning, with probability f

Only the ratio matters

Multiply f and p by the same number and you get the same forest running at a different speed. The one parameter that changes the behaviour is f / p: how many trees grow between two lightning strikes.

Why rule iv matters

Without lightning, a fire can only ever spread from an existing fire. Fires eventually die out, the forest fills in, and nothing more happens. Lightning is what keeps igniting fresh clusters — and, as it turns out, what tunes the system to its critical state without anyone setting a parameter by hand.

The step function

All four rules read state and write into new_state. That is the whole trick behind a parallel update: no cell ever sees a neighbour that has already moved on to the next time step.

R/forest_fire.R — ff_step()
ff_step <- function(state, p, f, periodic = FALSE) {
  n <- length(state)

  is_tree    <- state == TREE
  is_empty   <- state == EMPTY
  is_burning <- state == BURNING

  # All four rules read `state`, the configuration at the previous time step,
  # and write into `new_state`. This is what makes the update parallel.
  new_state <- state

  # (i) burning trees leave behind empty ground
  new_state[is_burning] <- EMPTY

  # (ii) + (iv) a tree catches fire from a neighbour, or from lightning
  neighbour_fire <- ff_neighbour_burning(is_burning, periodic = periodic)
  lightning      <- matrix(runif(n) < f, nrow(state), ncol(state))
  new_state[is_tree & (neighbour_fire | lightning)] <- BURNING

  # (iii) empty ground regrows; sites that burned this step stay empty until
  #       the next one, because `is_empty` refers to the previous state
  growth <- matrix(runif(n) < p, nrow(state), ncol(state))
  new_state[is_empty & growth] <- TREE

  new_state
}

A subtlety worth pausing on

Rule iii uses is_empty, computed from the old state. So a cell that burns down during this step stays bare until the next one — it cannot burn and regrow in the same instant. Swap in new_state == EMPTY and you quietly change the model.

04

Finding the burning neighbours

Rule ii needs one question answered for every cell at once: is any of my four neighbours burning? Looping over 40 000 cells in R to ask that is painfully slow. Shifting the whole matrix instead is fast, and it is the one piece of the code worth reading twice.

Take the lattice of burning cells, slide a copy of it one row down, and any cell now sitting under a TRUE has a burning neighbour above it. Do that in all four directions and combine with |.

Shift, then combine — one burning cell, 6 × 6 lattice

Orange is the burning cell; green marks the cells that rule ii will set alight next step. Each shifted copy contributes one direction.

The edges need a decision: what is beyond the map? Padding the matrix with a ring of FALSE means fire simply dies at the boundary. The alternative, wrapping the edges into a torus, is a one-line change.

R/forest_fire.R — ff_neighbour_burning()
ff_neighbour_burning <- function(burning, periodic = FALSE) {
  nr <- nrow(burning)
  nc <- ncol(burning)

  if (periodic) {
    # Cyclic index vectors: row 1's "up" neighbour is row nr, and so on.
    up    <- c(2:nr, 1L)
    down  <- c(nr, 1:(nr - 1L))
    left  <- c(2:nc, 1L)
    right <- c(nc, 1:(nc - 1L))
    burning[up, ] | burning[down, ] | burning[, left] | burning[, right]
  } else {
    # Pad with a ring of FALSE, so cells outside the lattice never ignite.
    padded <- matrix(FALSE, nr + 2L, nc + 2L)
    padded[2:(nr + 1L), 2:(nc + 1L)] <- burning
    padded[1:nr,             2:(nc + 1L)] |  # neighbour above
    padded[3:(nr + 2L),      2:(nc + 1L)] |  # neighbour below
    padded[2:(nr + 1L),      1:nc]        |  # neighbour left
    padded[2:(nr + 1L), 3:(nc + 2L)]         # neighbour right
  }
}

What to look for

Fires do not flicker in place — they travel. A strike lands, and a thin front eats across a connected patch of forest over many steps, leaving bare ground behind it that slowly greens over. The bigger the patch it lands in, the longer the fire lives.

06

What emerges

Nothing above mentions a forest density, a fire size, or a pattern. All of those are consequences. These two charts come from R/figures.R — 1500 recorded steps and 65 000 measured forest clusters on a 200 × 200 lattice.

A density that holds itself steady

Fires with no typical size

When lightning strikes a tree, the whole connected patch it belongs to burns. So the sizes of fires are the sizes of forest patches — and those follow a power law, N(s) ∝ s−τ, close to straight over three decades on log axes.

Where this demo departs from the paper

Drossel and Schwabl report a mean density of 0.39; this lattice settles near 0.44. Two honest reasons: f/p = 0.001 is not the f/p → 0 limit the theory assumes, and at 200 × 200 the largest fires run into the edge of the map. The paper is explicit that the lattice must be much larger than the biggest forest cluster. Shrink f/p, grow the lattice, and the number falls towards 0.39.

Try changing something

The fastest way to understand a model is to break it. A few edits worth making in R/forest_fire.R:

ChangeWhat you should see
periodic = TRUEFire wraps around the edges; no more boundary where fires go to die
Add the diagonal neighboursFire spreads more easily, forest density drops
Make p vary in spaceProductivity gradients — fires stall in the slow-growing half
Give burning cells two stepsFires that smoulder; fronts become thicker bands

The wrapper below runs the model without any plotting, and hands back the density series plus the final lattice — a good starting point for your own analysis.

R/forest_fire.R — ff_simulate()
ff_simulate <- function(steps, size = 200L, p = 0.02, f = 2e-5,
                        periodic = FALSE, state = NULL) {
  if (is.null(state)) state <- ff_init(size)

  out <- data.frame(
    step    = seq_len(steps),
    trees   = NA_real_,
    burning = NA_real_
  )

  for (i in seq_len(steps)) {
    state <- ff_step(state, p = p, f = f, periodic = periodic)
    out$trees[i]   <- mean(state == TREE)
    out$burning[i] <- mean(state == BURNING)
  }

  attr(out, "final_state") <- state
  out
}
